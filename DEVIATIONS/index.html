    Deviations from JCVI¶

    Rule (from the extraction brief): ported features reproduce JCVI v1.6.7 exactly. When JCVI has a bug, the original behaviour stays the default, an opt-in flag enables the fix, and the case is recorded here. Entries marked proposed are awaiting a decision (see open questions in the Phase 0 checkpoint).

    A. JCVI v1.6.7 defects found while generating golden outputs (Phase 0)¶

    Decision (project owner, 2026-09-28): a defect that makes a feature crash is fixed by default in MCscan3 (there is no behaviour to preserve). The parity reference for such a feature is JCVI v1.6.7 plus the minimal fixes in tools/jcvi_fixes.patch (every changed line is marked MCSCAN3 FIX A.<n>), run in .venv-jcvi-patched; those golden cases end in -fixed. Defects that silently change results are kept as the default with an opt-in fix.

    Each is reproduced by a golden case whose exitcode.txt is non-zero and whose cmd.txt carries a note.

    # JCVI location Symptom Trigger Golden case Proposed MCscan3 handling
    1 compara.catalog.layout TypeError: 'zip' object is not subscriptable always (Python 3) ortholog/layout/fixture fixed (list of columns; also pairwise_distance, used by --sort for rows missing from the BED); reference ortholog/layout/*-fixed
    2 algorithms.graph.merge_paths (used by synteny spa) DiGraph has no attribute edges_iter always (networkx ≥ 2) synteny/from-spa/* fixed (edges()); reference synteny/from-spa/*-fixed
    3 algorithms.ec.eaSimpleConverge (used by synteny layout) UnboundLocalError: updated when generation 1 does not beat the initial best synteny/layout/grape-peach fixed (updated = 0); reference synteny/layout/grape-peach-fixed
    4 formats.bed.intersectBed_wao (used by fractionation validate, gffselect) bytes joined with str always (Python 3) fractionation/validate/*, fractionation/gff-select/* fixed (text output); references *-fixed
    5 compara.synfind --scoring=density UnboundLocalError: orientation --scoring=density synfind/run/density proposed: fix; default collinear unaffected
    6 compara.ks clustal_align_protein / muscle_align_protein MultipleSeqAlignment has no format Biopython ≥ 1.79 ks/calc/modern-biopython (goldens for ks calc were made with Biopython 1.78) done: format(aln, "fasta"); output identical to the Biopython 1.78 goldens
    7 compara.ks.gc3 csv writerow() given a KsLine always ks/gc3/default fixed (write the row fields); reference ks/gc3/default-fixed
    8 compara.ks.batch generated Makefile calls python -m jcvi.apps.ks (module does not exist; it is jcvi.compara.ks) always ks/batch/grape-peach (makefile only) done: MCscan3 writes mcscan3 ks prepare/calc commands; rest of the makefile identical
    9 compara.catalog.omgprepare → get_edges (used by omg, enrich) RBH weights written as floats (c /= 10), later int("10.0") fails whenever non-syntenic RBH pairs pass the cutoff ortholog/enrich/fixture not a crash in omg-prepare itself, so kept by default; omg-prepare --integer-weights writes c // 10 (Python 2 behaviour); ortholog enrich reads float weights (int(float(c))), reference ortholog/enrich/*-fixed
    10 graphics.base.discrete_rainbow (used by phylo prepare) zip subscripted always (Python 3) phylo/prepare/* fixed (list); reference phylo/prepare/*-fixed
    11 apps.phylo.build str regex on bytes always (Python 3) phylo/build/family0 fixed (text); references phylo/build/family0-fixed, family0-ml
    12 apps.phylo._draw_trees odict_keys subscripted always (Python 3) phylo/draw/fixture proposed: list
    2b algorithms.graph.transitive_reduction (used by synteny spa) add_edge(a, b, w) (networkx 1.x signature) always synteny/from-spa/*-fixed fixed (add_edge(a, b, **w))
    10b apps.phylo.prepare writes leaf colours to an unopened file unless --writecolors without --writecolors phylo/prepare/*-fixed fixed (write only with --writecolors)
    11b apps.phylo.run_gblocks expects <aln>-gb; current Gblocks builds write <aln>-gb.fa Gblocks 0.91b (bioconda) phylo/build/family0-fixed fixed (accept -gb.fa)
    12b apps.phylo._draw_trees passes barcodefile/leafcolorfile (not accepted by draw_tree) and a Newick string instead of a tree object always phylo/draw/fixture-fixed fixed (arguments dropped: those two options have no effect; tree parsed first)
    13 graphics.ribbon.Synteny debug log indexes orientation when it is None layout with custom range and no --reorient (goldens use --reorient=F,F) fixed (the log line no longer indexes it)
    14 compara.ks.report --fit needs external gmm-bic binary (not packaged); fails on shapes --fit plot/ks/report-fit fixed: MCscan3 fits the log-normal mixture itself (EM on log Ks, deterministic start); no external program
    15 compara.catalog tandem --help, formats.blast rbbh --help --help crashes: unescaped % in help text --help only — fix (cosmetic, no output change)
    16 formats.bed fix/some logger.debug("...%s".format(x)) never interpolates logging only — fix (logging only)
    17 compara.catalog tandem raw LAST output (with # lines) raises KeyError: '#' LAST tabular input goldens use the filtered BLAST proposed: skip comment lines
    18 apps.phylo.merge_rows_local (used by phylo prepare --addtandem) IndexError a merge among the last 10 rows unit test test_merge_rows_local fixed (row count updated after each merge)
    19 graphics.dotplot --synteny passes the BED files as scan distances (TypeError), then unpacks (x, y, value) points as pairs always — fixed (default distances; box from x, y)
    20 compara.ks my_hist --fill (ks report --pdf --fill, multireport --fill) pylab.poly_between was removed from matplotlib --fill — fixed (same polygon, computed directly)
    21 graphics.synteny --tree passes the Newick string to draw_tree, which needs a tree object --tree — fixed (tree parsed first)
    22 graphics.ribbon logger.info(..., file=sys.stderr) (TypeError) with --annotations/--extra-annotations or --scalebar; --tree unpacks 3 of 4 fields and passes a Newick string; an 11-column layout line indexes column 12; a wrong number of --reorient values exits with status 0 those options / inputs unit tests in test_plot_ribbon.py fixed (the last one now fails with an error)

    C. Platform and representation notes (no behaviour change intended)¶

    Topic Original MCscan3
    BLAST line class compiled Cython (cblast); falls back to a pure-Python class that formats numbers differently one pure-Python BlastLine that reproduces the compiled class exactly (verified on 185,849 real hits + edge cases)
    %g formatting of BLAST e-values/scores C sprintf, so output depends on the C library. macOS libc keeps a trailing zero on exact ties that round down (%.2g of 205 → 2.0e+02; glibc → 2e+02) reproduces the golden outputs (macOS) on every platform; MCSCAN3_PRINTF=standard gives C-standard %g. Emulation validated on 715,115 conversions
    BlastLine.orientation compiled class exposes a C char, i.e. the integers 43/45, so Python code comparing with "-" never matches (only affects out-of-scope blast chain/condense) the strings "+"/"-"
    HiGHS solver not available opt-in backend, run in a worker process (OR-Tools bundles HiGHS; both in one process can crash)
    ortholog omg-parse output order Python set order of groups, per glob file order files and groups sorted; same groups
    synteny matrix row/column order Python set order of chromosome names (changes with the hash seed between runs) natural sort order; identical counts
    phylo prepare gene order within each family file Python set order (changes with the hash seed between runs) column order of the MCscan row; same records
    phylo build ML tree (PhyML) PhyML seeds its random generator from the clock, so reruns (JCVI's too) may root the same tree differently or differ in the last digit of a branch length same; parity tests compare unrooted splits and branch lengths
    phylo build NJ tree EMBOSS PHYLIP via Biopython wrappers (removed from current Biopython) the same programs and options, called directly; not verified here (EMBOSS is not packaged for osx-arm64)
    Figure theme seaborn set_theme (notebook context, deep palette, --style), which also remaps the colour codes "k", "g", ... the same rcParams and colour codes, recorded as data (tools/gen_plot_data.py); no seaborn dependency. Figures are pixel-identical (PNG) and identical apart from metadata (SVG, PDF)
    ColorBrewer palettes palettable the same colour tables, recorded as data; no palettable dependency
    plot histogram figures R/ggplot2 (Rscript required) matplotlib, in ggplot2's default look; same data, bins and file names (<file>.<format>; the original always wrote .pdf unless --base). The text mode is byte-identical
    Dot plot grid colour option --theme (Set1 colour index) --grid-color; --theme selects the figure theme (classic or mcscan3). The legacy layer translates --theme
    Figure metadata Creator: Matplotlib ... Creator: MCscan3 <version> (PNG, PDF, SVG); nothing visible
    plot microsynteny --glyphcolor=orthogroup colours hash(orthogroup), which changes with the hash seed between runs a CRC32 of the sorted group members: the same colours on every run (the default orientation colouring is unaffected)
    must_open supports s3://, prompts before overwriting with checkexists=True no S3, never prompts

    B. Behaviour questions (not bugs)¶

    Topic JCVI behaviour Question
    gff bed --primary_only keeps the first transcript per gene Owner asked for longest-isoform prep: add opt-in --longest (Phase 6.1 / prep gff2bed)
    ASCII plots (ks report, histogram --ascii) print literal rich markup such as [green] and, because of a format bug, the line [bold white] instead of the title Decided: byte-identical by default; --plain prints the title and no markup
    fractionation offdiag hard-codes B. napus chromosome names (A0x/C0x) Port as-is, or mark legacy-only like napus/merge/segment?
    Report text on stderr synteny summary/stats, ks report, fractionation diff print results to stderr mixed with log lines Decided: MCscan3 also prints reports to stderr (plain text; log lines have their own mcscan3: format), keeping stdout for data. Parity tests compare the report lines of both.
