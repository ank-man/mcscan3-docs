    Checkpoint reports¶

    Checkpoint 3b: all analysis groups ported (2026-09-29)¶

    Parity¶

    Every analysis feature (all groups except plot, and phylo draw, which is a figure) is parity-verified: its outputs are byte-identical to the JCVI v1.6.7 golden outputs, and its report text matches the original's.

    Group Features Status
    prep 4 all parity-verified
    align 3 all parity-verified
    filter 4 all parity-verified
    synteny 19 all parity-verified
    quota 1 parity-verified
    ortholog 8 all parity-verified
    ks 8 all parity-verified (multireport and the report --pdf figure are verified by image comparison)
    fractionation 7 + 4 7 parity-verified; napus, merge, segment, offdiag are legacy-only (hard-coded B. napus study code)
    ancestral 5 all parity-verified
    pad 2 all parity-verified
    synfind 1 parity-verified (both scoring modes)
    phylo 2 of 3 prepare, build parity-verified; draw is ported with the graphics (Phase 4)

    Ten features crash on every run in JCVI v1.6.7. For these, the reference is JCVI plus the minimal fixes in tools/jcvi_fixes.patch (the golden cases ending in -fixed, decided at Checkpoint 0). All other outputs come from unmodified JCVI.

    What the parity tests do not cover byte-for-byte, and why:

    • phylo build: PhyML seeds its random generator from the clock, so two JCVI runs may root the same tree differently. Trees are compared as unrooted splits with branch lengths. The NJ step needs EMBOSS PHYLIP, which is not packaged for osx-arm64; its failure path matches the golden, but its success path is untested.
    • align blast/align diamond stdout (tool chatter with timestamps) and the report of ortholog run with BLAST/DIAMOND.
    • phylo prepare gene order within each family file (hash-seed dependent in the original).

    Deviations¶

    See DEVIATIONS.md. In summary:

    • 20 JCVI defects are catalogued (section A). Crashes are fixed by default; silent result changes keep the original behaviour, with an opt-in fix.
    • Platform and representation notes are in section C. These include C printf and Cython BlastLine emulation, the Unix sort emulation, sorted outputs where the original order depended on the hash seed, and the dropped seaborn/palettable/R dependencies.

    Runtime versus JCVI¶

    tools/bench.py runs each golden case with JCVI (golden environment) and MCscan3 (fresh processes, same inputs). Times are wall-clock seconds, from one run on an Apple-silicon laptop.

    Area JCVI MCscan3 Ratio
    prep (gff2bed, fasta-format, bed) 0.5–3.1 s 0.4–3.1 s 0.69–1.07
    align last / blast (aligner-bound) 7–50 s 6–57 s 0.89–1.14
    filter blastfilter / cscore / rbbh 0.6–1.1 s 0.6–1.2 s 0.80–1.05
    filter best 0.6–0.7 s 0.7–0.8 s 0.97–1.22
    synteny (19 features) 0.5–4.5 s 0.2–1.1 s 0.09–1.00
    quota align 1.0–1.3 s 0.6–0.8 s 0.58–0.61
    ortholog run (end to end, incl. LAST/BLAST/DIAMOND) 14–79 s 9–73 s 0.66–0.98
    other ortholog, ks, fractionation, ancestral, pad, synfind, phylo 0.4–7 s 0.2–3.2 s 0.06–0.97

    The BLAST-line question from Phase 2: the pure-Python BlastLine is 3.8x slower than the compiled original per line. End to end, it is not a bottleneck. filter blastfilter runs at 0.80–1.02x JCVI, synteny scan at 0.63–0.73x, and ortholog run at 0.66–0.98x, because MCscan3 starts faster and avoids subprocess round trips. No compiled accelerator is needed.

    The only case above 1x beyond measurement noise was filter best, which sorts the BLAST file like Unix sort. The emulation now uses stable key passes instead of a comparison function (7x faster, identical order), which brought it from 2.3–3.3x down to 0.97–1.22x.

    Checkpoint 4: graphics ported (2026-09-29)¶

    All 13 plot features, ks multireport, phylo draw and the dot plot of ortholog run are ported and parity-verified. The original look is the default (--theme classic), and --theme mcscan3 gives the house style. mcscan3 plot gallery renders every figure in both themes next to the original's reference (see Figures and gallery).

    What made exact parity possible¶

    • The seaborn theme values that JCVI applies (rcParams and remapped colour codes, for example "k" drawn as #1a1a1a) are recorded as data, as are the ColorBrewer tables. Neither seaborn nor palettable is a dependency.
    • Each figure starts from a clean matplotlib state, as a fresh JCVI process did.

    Crashes fixed while porting the graphics (see DEVIATIONS.md)¶

    dotplot --synteny (A.19), ks --fill (A.20), synteny --tree (A.21), ribbon without --reorient (A.13), ribbon with --annotations, --scalebar, --tree or 11-column layouts (A.22), and the phylo draw crash (A.12). ks report --fit works without the external gmm-bic program (A.14).

    Phase 6: new analyses (2026-09-29)¶

    These are the features requested after the extraction (see ROADMAP.md). Each reimplements a published method from its paper, with no code taken from those tools, and cites it on its documentation page. Their registry status is new.

    Command Method How it is tested
    prep genome longest coding transcript per gene, CDS spliced from the genome and translated synthetic genome (minus strand, phase, isoforms, non-coding); same transcripts as prep gff2bed --longest on the peach annotation
    dup classify DupGen_finder classes, from the paper synthetic genome with a known class for every pair; grape run looks plausible
    ortholog soi Orthology Index filtering (SOI) constructed blocks with known OI; pairs, OrthoFinder and BLAST RBH inputs
    wgd ksd paranome (MCL + node weighting) or anchor Ks; yn00 or codeml (pairwise ML) anchor Ks equals JCVI ks calc (golden) to 1e-3; node weights on a known family
    wgd peaks, wgd mix, wgd blocks KDE peaks; GMM, ELMM (exponential background + log-normal peaks) and Bayesian GMM, chosen by BIC/AIC, multi-start EM, warm-start bootstrap intervals, saturation warning; per-block median Ks ELMM recovers background + peak and picks the no-WGD null on exponential data; weights equal repeated data; grape: the paranome ELMM and the block-level GMM both put γ at Ks 1.36
    wgd correct relative rate correction with an outgroup (ksrates) exact numbers; bootstrap on synthetic distributions
    wgd tree-map Tree2GD-style LCA reconciliation duplications at known nodes; rooting, support and coverage filters
    pan genes, plot riparian GENESPACE-style pan-genes and braids three synthetic genomes with transitive synteny and neighbour placement; colour propagation
    network build, cluster, profile, tree synteny networks (Zhao & Schranz) four synthetic species: clusters, profiles and the tree ((A,B),(C,D))

    The full suite has 386 tests, plus 22 slow tests that run external aligners. mypy and ruff are clean.

    Figures, report and documentation site (2026-10-15)¶

    The figures, the pipeline and the documentation were made into one consistent system.

    • House style (mcscan3.plot.style). Every figure that is new in MCscan3 shares its colours, fonts, layout, title and subtitle, and output settings. The mcscan3 theme lists only fonts that are installed, which ends a flood of findfont warnings. Ported figures keep --theme classic byte for byte.
    • Modern dot plot. Chromosome names are shortened and non-overlapping, unplaced scaffolds are hidden (with a note), and the heading is measured to sit above the labels.
    • Interactive dot plots (plot dotplot -o x.html, and every pair in the report). The page draws on a canvas: zoom, pan, click a chromosome to zoom to it, see the genes on hover, and colour by orientation, block or Orthology Index. It needs no network access.
    • Pipeline. run.json records the status, time and notes of every step, plus the report's results. --steps re-runs only the steps given; pipeline report <outdir> rebuilds the report. A table of the steps is printed at the end of each run.
    • Report. Sidebar, summary cards, interactive dot plots, stacked bars, lightbox, sortable tables, dark mode and a table of the run.
    • Documentation site. Material for MkDocs with tabs, a landing page, a gallery made from a six-eudicot run (tools/make_docs_gallery.py) and an embedded interactive dot plot. GitHub Pages deploys it (.github/workflows/docs.yml), and the build fails if the command pages are out of date.
    • Fixes. network plot --kind profile crashed with a RecursionError: with few genomes, scipy's dendrogram recursed through a chain-like tree. The dot plot's orientation palette crashed when some anchors were on hidden scaffolds.

    Validated by re-running the six-eudicot pipeline (all steps done), and by checking the report and the site in headless Chromium (no script errors; hover, zoom and pair switching all work).

    WGDs placed by syntenic paralogs in gene trees (2026-10-22)¶

    • Anchored placement (wgd tree-map --paralogs pairs.tsv --outgroup X). This reimplements PUG (McKain et al. 2016) from the paper:
    • gene trees are rooted on the outgroup's genes when they form a clade, else on the fewest duplications;
    • each paralog pair's last common ancestor is mapped to the species tree, and kept when both child clades hold at least half the species below it;
    • each gene tree gives one vote per event and node;
    • supports, when present, are filtered, and votes at ≥80% support are counted separately.

    It writes <prefix>.events.tsv. * wgd consensus, gene-tree line. * The noisy count of duplication bursts is replaced. Each genome's self-synteny anchors are labelled by the Ks mixture component of their block, then placed in the gene trees (consensus.events.tsv). * A Ks peak with fewer than --min-tree-rate (0.05) gene trees per pair is rejected, and it loses its Ks vote too. Such pairs come from tandem arrays or a few large families. * A placement split between two adjacent branches is flagged as possible allopolyploidy. * Bursts remain the fallback when there are no syntenic paralogs. * Counting. Ks peaks less than 1.35 times apart count as one event. Ks and gene-tree counts are capped by the copy ratios when those saw events on the branch. * Fixes. * wgd consensus computed ortholog Ks with PAML yn00, so without PAML the Ks line silently gave nothing. It now uses the native LPB93 estimator, like pipeline run --ks. * pipeline run --steps lost the reference, tree and orthology of the earlier run and reran the all-vs-all orthology search. _previous now restores them, and run.json also records the orthologues directory.

    Validated on the six-eudicot run (OrthoFinder gene trees, 12,112 used) with the OrthoFinder species tree and with the accepted one. The calls:

    branch before now
    core-eudicot stem γ triplication γ triplication (4/4)
    Arabidopsis missed α and β (2/4; 4/4 on the accepted tree)
    soybean 2 WGDs 2 WGDs
    poplar 1 WGD 1 WGD
    grape false 1 WGD none

    The false grape call came from a Ks component at 0.35: 7,594 pairs in only 60 gene trees, now rejected. Grape's γ peak (Ks 1.45) and peach's (1.64) are placed on the core-eudicot stem by the gene trees, even where Ks alone placed peach's deeper.

    2026-10-22: benchmark framework, synteny-constrained anchoring, MMseqs2, annotation transfer¶

    Work for the NAR paper (docs/development/PAPER_PLAN.md).

    • bench simulate / bench score. A genome-evolution simulator that writes a known answer:
    • codon-level divergence with a per-gene ω, so Ks matches the branch length;
    • rearrangements, tandem and dispersed duplications, and losses;
    • WGDs, triplications and allopolyploidy, with biased fractionation;
    • a genealogy-based truth: orthologs, ohnologs, positional pairs, events and ancestral orders.

    bench score gives the precision and recall of anchors against that truth. * synteny anchor. Synteny-constrained anchoring, reimplemented from the GENESPACE paper: * collapses tandem arrays; * chains on condensed gene ranks; * rescues hits within a buffer; * finds secondary blocks.

    New in MCscan3 is block-local best-hit extension with a C-score filter. The new defaults are --hits 2 (4 for a genome against itself), --secondary 3 and --mask-buffer 100. They were tuned on the simulated polyploids, where F1 is at least 0.998 in every case. * align mmseqs, and ortholog run --align-soft mmseqs. * annotate transfer. Annotation transfer from one or more references: * splice alignment with minimap2; * each gene's copy chosen by synteny with its flanking anchors; * ORF check and repair; * a union across references. * benchmarks/. A synteny benchmark with these methods, all run on shared DIAMOND hits: MCscan3 anchor, MCscan3 classic, MCScanX and GENESPACE 1.3.1. Peak memory comes from /usr/bin/time. * CLI help. [default: …] text was being stripped by rich markup; it now reads (default: …).
