    MCscan3 extraction plan¶

    Source: JCVI v1.6.7 (e10b884), see SOURCE_VERSION.md. Generated with tools/inventory.py (actions) and tools/import_graph.py (imports).

    1. Inventory vs. Feature Map¶

    tools/inventory.py confirms every action in the Feature Map exists in JCVI v1.6.7, and that every action of the fully in-scope modules (compara.*, apps.phylo, graphics.* listed) is mapped. Differences and corrections:

    Item Finding Proposed action
    align diamond Not new. JCVI has apps.align.diamond_blastp_main (a function, not a listed action), used by catalog ortholog --align_soft diamond_blastp. Port it as a normal feature; JCVI source = apps.align diamond_blastp_main.
    plot dotplot No main(); entry point is dotplot_main() under if __name__ == "__main__". Map to graphics.dotplot dotplot_main.
    plot blastplot No main(); argument parsing is inline in the __main__ block. Map to graphics.blastplot __main__.
    prep gff2bed longest isoform JCVI gff bed --primary_only keeps the first transcript seen per --parent_key, not the longest. There is no longest-isoform option in gff bed. Parity: keep first-seen as --primary-only. Proposal: add opt-in --longest (new, documented in DEVIATIONS). Needs confirmation.
    quota align solvers v1.6.7 solves via OR-Tools pywraplp (bundled SCIP backend) first; external scip / glpsol binaries are only fallbacks. Default: OR-Tools SCIP (parity). Fallbacks: GLPK (glpsol), external SCIP. Add HiGHS (highspy) as opt-in.
    compara.phylogeny lcn Low-copy-number gene selection from OrthoFinder output. Not MCscan-related. Out of scope.
    compara.pedigree Pedigree/inbreeding. Not MCscan. Out of scope.
    graphics.align, graphics.wheel, graphics.landscape, graphics.mummerplot, graphics.coverage, graphics.table, graphics.assembly, graphics.grabseeds Not MCscan-related. Out of scope.
    fractionation napus/merge/segment Project-specific (B. napus). legacy-only unless Haibao confirms.

    Minor JCVI bugs noticed so far (logging only, no output change): formats.bed fix/some call logger.debug("...%s".format(x)), so the value is never interpolated. Will record in DEVIATIONS.md when ported.

    2. Import graph summary¶

    The JCVI internal graph is densely cyclic (apps.base ↔ formats.base ↔ utils.cbook, formats.sizes ↔ formats.agp, etc.), so the transitive closure of every in-scope module is ~35 modules including assembly, AWS, grid, OBO/GO, SAM, and uclust code. Almost all of that is reached only through module-level imports used by out-of-scope actions. The plan below is therefore driven by the names that in-scope code actually calls (tools/import_graph.py --names).

    3. Decision per dependency¶

    Legend: core = port into mcscan3.core, io = port into mcscan3.io, plot = port into mcscan3.plot, replace = use a standard library / third-party package, drop = not needed.

    apps¶

    JCVI module Names used by in-scope code Decision
    apps.base OptionParser, ActionDispatcher drop → Typer CLI (mcscan3.cli). Option names/defaults preserved per feature.
    logger replace → logging.getLogger("mcscan3") configured in mcscan3.log (rich handler optional).
    sh, popen, Popen, which, getpath, need_update, mkdir, cleanup, get_abs_path, glob, iglob core → mcscan3.core.shell (subprocess-based, same semantics incl. need_update skip logic). getpath reads tool paths from env vars (MCSCAN3_<TOOL>) instead of ~/.jcvirc.
    flatten, parse_multi_values, sample_N, datafile core → mcscan3.core.utils; datafile only needed for hg38 files in graphics.chromosome (see below).
    apps.align last, blast_main, diamond_blastp_main, run_lastdb, run_formatdb, run_diamond_makedb Feature modules features/align/{last,blast,diamond}.py.
    apps.grid MakeManager (only ks batch in scope) replace → write a Makefile as JCVI does (small port into core.shell), or run sequentially. Output parity is on the generated makefile + results.
    apps.r RTemplate (only graphics.histogram) drop → matplotlib reimplementation (spec).
    apps.phylo feature module Feature modules features/phylo/*.
    apps.fetch, apps.cdhit, apps.uclust, apps.biomart only via out-of-scope code drop

    formats¶

    JCVI module Names used Decision
    formats.base BaseFile, LineFile, DictFile, SetFile, must_open, read_block, flexible_cast, get_number, is_number, longest_unique_prefix, write_file io → mcscan3.io.base. must_open keeps -/stdout, .gz, .bz2 handling.
    formats.bed Bed, BedLine, BedSummary, sort, sizes, intersectBed_wao, merge, uniq io → mcscan3.io.bed (Bed, BedLine, order, order_in_chr, sort). intersectBed_wao → core.bedtools (calls bedtools intersect -wao, as JCVI). merge/uniq → prep features. Coverage, BinFile, pybedtools, histogram imports are only used by out-of-scope actions → drop.
    formats.blast Blast, BlastLine, filter, cscore, best, rbbh, filtered_blastfile_name, bed io → mcscan3.io.blast (Blast, BlastLine, BlastSlow); filter pieces used by the pipeline → core; cscore/best/rbbh → filter features.
    formats/cblast.pyx BlastLine (Cython) replace with pure-Python BlastLine (ported from formats/pyblast.py, __slots__). Benchmark vs. cblast in Phase 2; revisit (Polars / optional compiled ext) only if >3× slower.
    formats.pyblast BlastLine io (basis of the pure-Python reader).
    formats.fasta Fasta, translate, some, format replace Fasta with Biopython SeqIO.index wrapper (mcscan3.io.fasta); format → prep fasta-format; translate (used by ks prepare, phylo prepare) → port the function into mcscan3.io.fasta. formats.agp, formats.fastq, assembly.base imports → drop (out-of-scope actions only).
    formats.gff Gff, GffLine, bed io → mcscan3.io.gff (pure-Python line parser as in JCVI; gffutils, BCBio, annotation.reformat.atg_name, formats.obo only used by other actions → drop).
    formats.sizes Sizes io → mcscan3.io.sizes; build from FASTA with Biopython; agp helper drop.
    formats.sam, formats.fastq, formats.agp, formats.obo only out-of-scope drop

    compara (shared, non-feature code)¶

    JCVI Names used Decision
    compara.base AnchorFile io → mcscan3.io.anchors (AnchorFile, print_to_anchors, blast iterator, block splitting on ###).
    compara.synteny (shared parts) BlockFile, SimpleFile, check_beds, read_blast, batch_scan, get_orientation, _score, screen io: BlockFile → io.blocks, SimpleFile → io.simple. core: check_beds, read_blast, batch_scan, _score, get_orientation → mcscan3.core.synteny. Each action → its own features/synteny/*.py.
    compara.ks (shared) KsFile, AbstractCommandline, run_mrtrans, clustal_align_protein, muscle_align_protein, find_first_isoform io KsFile → io.ks; command wrappers → core.external (used by ks and phylo).

    algorithms / utils¶

    JCVI Names used Decision
    utils.grouper Grouper core → core.grouper
    algorithms.lis longest_increasing_subsequence, longest_decreasing_subsequence, heaviest_increasing_subsequence core → core.lis
    utils.range Range, range_chain, range_depth, range_distance, range_interleave, range_minmax, range_overlap, range_span, range_union, range_piles, LEFT, RIGHT core → core.range (drop more_itertools where trivial).
    algorithms.lpsolve MIPDataModel (+ SCIPSolver, GLPKSolver fallbacks) core → core.lpsolve. OR-Tools default; GLPK/SCIP executables; HiGHS optional. tsp, hamiltonian, min_feedback_arc_set drop (not used by in-scope code).
    algorithms.graph BiGraph (ancestral), merge_paths (synteny from-spa) core → core.graph (networkx). pygraphviz only for drawing in ancestral adjgraph → optional extra.
    algorithms.ec GA_setup, GA_run (synteny layout) core → core.ec with deap as optional dependency ([ga] extra). GA is stochastic: parity test must fix the seed and verify JCVI output is reproducible with it.
    algorithms.matrix, algorithms.maxsum, algorithms.supermap, algorithms.tsp only out-of-scope drop
    utils.cbook SummaryStats, gene_name, human_size, percentage, thousands, uniqify, seqid_parse, Registry, AutoVivification, fixChromName core → core.utils.
    utils.table tabulate, write_csv, banner core → core.table.
    utils.orderedcollections OrderedDict, DefaultOrderedDict, parse_qs replace → stdlib dict / collections; parse_qs → port into io.gff.
    utils.validator validate_in_choices, validate_in_range replace → Typer choices / click.IntRange.
    utils.aws via formats.base only drop
    assembly.base (calculate_A50), assembly.goldenpath, assembly.coverage formats.blast's summary/anchors actions only drop (the spec's formats.blast → assembly.base concern is resolved: not on any in-scope path).
    annotation.reformat, graphics.landscape only out-of-scope drop

    graphics¶

    JCVI Decision
    graphics.base (savefig, AbstractLayout, markup, latex, normalize_axes, set_human_axis, palettes set1/set2/set3, discrete_rainbow, draw_cmap, asciiplot, quickplot, …) plot → mcscan3.plot.base. savefig writes Creator: MCscan3 <version> metadata. setup_theme (seaborn) → mcscan3.plot.theme with a jcvi theme (default, parity) and an mcscan3 theme. palettable → inline the few palettes used. set_chinese_font, TeX detection kept minimal.
    graphics.glyph plot → mcscan3.plot.glyph; demo / gff actions → plot features.
    graphics.chromosome feature + shared Chromosome, HorizontalChromosome → plot.chromosome_glyphs. hg38 cytoband data files (datafile) → ship only if needed by in-scope options; otherwise drop (human-specific).
    graphics.synteny (Shade, ymid_offset) and graphics.tree (draw_tree, read_trees) shared helpers → plot, used by karyotype/microsynteny/ribbon. ete4 becomes a [plot]/[tree] optional dependency.
    graphics.histogram plot → matplotlib rewrite; ASCII mode (stem_leaf_plot, asciiplot) ported as-is. R dependency dropped (parity on ASCII text output; images compared at looser tolerance, documented).

    5. Golden-output coverage (Phase 0 result)¶

    tools/make_golden.sh defines 141 cases covering all 79 Feature Map commands (see tests/golden/INDEX.md).

    • 127 cases are reference outputs (JCVI succeeded); 14 are expected failures that document JCVI defects (docs/DEVIATIONS.md §A).
    • 69 features have at least one reference output.
    • 10 features have only expected-failure goldens because every invocation hits a JCVI defect: synteny from-spa, synteny layout, ortholog enrich, ortholog layout, ks gc3, fractionation validate, fractionation gff-select, phylo prepare, phylo build, phylo draw. These need a decision on what the parity reference should be (Checkpoint 0, question 1).
    • ks calc and phylo * goldens come from .venv-jcvi-legacy (Biopython 1.78).
    • Determinism verified with --check; the only differences between two JCVI runs are tool chatter on stdout and an R-generated PDF timestamp.

    6. Phase 2 results: shared core and file formats¶

    Ported: core.grouper, core.lis, core.range, core.utils, core.cformat (new), core.synteny (scan, liftover, BLAST-to-rank), core.lpsolve (OR-Tools default, SCIP/GLPK fallbacks, HiGHS opt-in), io.base, io.bed, io.blast, io.anchors, io.blocks, io.simple, io.sizes, io.layout.

    Parity: tools/make_unit_golden.py runs the original functions on the real test data and seeded random inputs; tests/core and tests/io recompute everything with MCscan3 and compare exactly (including OR-Tools selecting the same blocks on three real quota instances).

    BlastLine benchmark (185,849 lines, parse only, loaded machine): compiled original 0.17 s, MCscan3 pure Python 0.63 s (3.8x). The per-line micro-benchmark is above the 3x guideline; the relevant end-to-end comparison (filter blastfilter, synteny scan, ortholog run vs JCVI) is measured in Phase 3. If it stays above 3x, options are a vectorised reader for whole files or an optional compiled accelerator.

    Phase 3 note: ancestral adjgraph writes DOT through mcscan3.core.dot (a Graphviz-compatible writer) instead of pygraphviz; the output is byte-identical to the original's, so pygraphviz and the Graphviz C library are not needed.
